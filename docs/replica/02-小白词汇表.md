# 02 · 小白词汇表

> 本指南和 vibe coding 过程中会反复出现的名词，每条一句话讲人话。
> 可以当字典：卡住了就回来查，不用从头背。

## 编程基础

| 名词 | 人话解释 | 类比 |
|---|---|---|
| **JavaScript (JS)** | 让网页"动"起来的编程语言，浏览器天生就会运行它 | 网页的"血液"（HTML 是骨架，CSS 是皮肤，JS 是让它会动会想的神经） |
| **TypeScript (TS)** | 给 JS 加了"类型检查"的升级版：变量必须声明是数字还是文字，写错了编译时就报错，不用等到用户用崩了才发现 | 填表时有必填校验，防止把电话填成"abc" |
| **Node.js** | 让 JS 跑出浏览器的"环境"——用它写服务器程序 | 原来只在浏览器里游的鱼，现在能去河里（服务器）游泳了 |
| **vibe coding** | 你负责说人话描述"要什么"，AI 负责写代码；你验收结果、提修改意见 | 你是甲方兼验收员，AI 是施工队；你不学砌砖，但你得会看"门朝哪开" |
| **前端 / 后端** | 前端 = 用户看到的界面（浏览器里）；后端 = 幕后的服务器（管数据、调 AI） | 前端是餐厅前厅，后端是后厨+仓库 |
| **全栈** | 前端后端都会（或都用一套语言写） | 既会炒菜的又懂装修的"全能师傅" |
| **API** | 两个程序之间的"约定好的对话窗口"，你按格式发请求、它按格式回数据 | 餐厅点单窗口：你按菜单点（请求），后厨按单子出（响应） |
| **API key** | 调用别人服务（大模型）的"身份证+账本号"，调一次记一次费 | 健身房的会员卡：证明你是谁，刷一次扣一次钱 |
| **token** | 大模型计费/计量的单位，大约 1 个中文字 ≈ 1~2 token，1 个英文单词 ≈ 1 token | AI 按"字"收费的"字数" |

## 前端相关

| 名词 | 人话解释 | 类比 |
|---|---|---|
| **React** | 目前最主流的网页界面框架，把界面拆成"小组件"像拼乐高一样组装 | 装修用的"预制模块化板材"，一块块拼出整个房子 |
| **SPA（单页应用）** | 整个网站只有"一个网页"，切换功能时不刷新页面，靠 JS 换内容 | 一扇窗看全场：不是每次进新房间都重新开门（传统多页），而是幕布一拉就换景 |
| **Vite** | 前端"打包器"：把你的源码加工压缩成浏览器高效运行的产物；开发时启动秒开 | 后厨的备菜台：把生料加工好，端出来就是成品 |
| **Next.js** | 基于 React 的全栈框架：网页 + 服务端接口在一个项目里，部署省事 | "带后厨的餐厅"：一个项目里既有前厅又有传菜口 |
| **CSS** | 控制样式（颜色、字号、位置）的语言 | 装修图纸（刷什么漆、挂哪面墙） |
| **CSS-in-JS** | 把样式写在 JS 文件里而不是单独的 CSS 文件（LobeHub 用 antd-style 干这个） | 装修说明贴在对应家具背面，而不是单独一沓图纸 |
| **组件（Component）** | 可复用的 UI 小块：按钮、输入框、弹窗……一个组件 = 一小段功能代码 | 乐高积木：门把手是一个件，装 10 个房间复用 10 次 |
| **状态（State）** | "程序当前情况的记录"：登录没登录？打开了哪个会话？输入框里是什么字 | 便签墙：随时记着"现在到哪一步了" |
| **Zustand** | 一个很轻的状态管理库（LobeHub 前端用它），本质是个"共享便签本"，任何组件都能读写 | 服务台的便签墙：前厅后厨都看同一面墙，不各记各的 |
| **SWR** | 数据获取库：帮你发请求、缓存结果、自动刷新（LobeHub 前端用它） | 跑腿小哥：你去过的数据他记着，下次直接给你，过期了再跑一趟 |
| **HMR（热更新）** | 开发时改一行代码，浏览器瞬间更新那部分，不用整页刷新 | 换掉一张桌布不用拆桌子 |
| **PWA** | 把网页做成"准 App"（可安装到手机/桌面，能离线一部分功能） | 网店做成"可装进手机的应用" |

## 前后端通信 / 服务端

| 名词 | 人话解释 | 类比 |
|---|---|---|
| **tRPC** | LobeHub 用的前后端通信框架：前端调后端像调本地函数一样，参数和返回自动类型检查，几乎不写"接口文档" | 前后厨的对讲机：喊"3 号桌的糖醋排骨加辣"就行，不用念一段电报码 |
| **SSE（Server-Sent Events）** | 服务器向浏览器"持续推流"的技术；LobeHub 的"打字机效果"就靠它（AI 边生成边推，浏览器边收边显示） | 广播电台：主播边说边播，听众跟着听，而不是等录完整张专辑再给 |
| **流式（Streaming）** | 数据"挤牙膏"式一点点传，而不是攒完整再一次性给 | 上面那个广播/挤牙膏的效果 |
| **数据库（DB）** | 结构化存储数据的软件；LobeHub 用 PostgreSQL | 有编号货架的仓库：找货按编号，不靠人记 |
| **PostgreSQL** | 最主流的开源关系数据库之一（表格型存储） | 大型立体仓库 |
| **SQLite** | 文件型数据库：整个库就是一个 .db 文件，零安装零运维——**小项目起步首选**（建议你先用它） | 桌面小铁盒：东西不多时比立体仓库好使 |
| **ORM** | "对象关系映射"：用代码对象代替手写 SQL 语句来增删改查（LobeHub 用 Drizzle） | 仓库管理 App：点按钮入库出库，不用背格子编号（SQL） |
| **Drizzle** | LobeHub 用的 ORM 库，用 TS 代码描述表结构，生成数据库迁移 | 货架规则的手写版：规则写在代码里，仓库照此施工 |
| **迁移（Migration）** | 数据库结构变更的版本化脚本（"第 3 版：新增 xx 表"） | 装修施工单：每次改墙都留一张单，可随时重放 |
| **鉴权 / 认证（Auth）** | "你是谁"：登录、发凭证、验证凭证（LobeHub 用 better-auth） | 保安查工牌：进门前先确认你是谁 |
| **CORS** | 浏览器安全规则：网页只能调"白名单"里的服务器接口；新手最常见的"前端调不到后端"报错就是它 | 小区门禁：快递只放白名单楼号，不登记就扔门口 |

## AI 相关

| 名词 | 人话解释 | 类比 |
|---|---|---|
| **LLM（大语言模型）** | AI 的"大脑"：GPT、Claude、通义千问这些，你通过 API 租来用 | 外聘的专家：不养在自家，用时打电话付费 |
| **模型提供商（Provider）** | 卖 LLM API 的公司/服务（OpenAI、Anthropic、阿里云、Mistral…）；LobeHub 有 50+ 适配器 | 专家劳务市场：不同领域的专家在不同机构 |
| **系统提示词（System Prompt）** | 给 AI 的"岗前培训"：定义它的角色、规则、语气（LobeHub 里每个 Agent 的人设就是这个） | 岗位说明书 + 员工手册 |
| **温度（Temperature）** | 0~1 的参数：越低回答越保守、固定，越高越发散、有创意 | 员工"自由发挥度"：0=照本宣科，1=允许创新 |
| **Function Calling / 工具调用** | 让 AI 在回答中"打电话"：不是它自己会算，而是它能说"帮我调计算器/查网页"，程序执行后把结果喂回去 | 专家不会跑腿，但会打电话让前台代跑，拿到结果再答题 |
| **MCP（Model Context Protocol）** | 工具调用的"USB-C 标准"：任何工具按这个标准接上，任何支持 MCP 的 AI 都能用，不用逐个适配 | USB-C 接口：一个口接显示器/充电/硬盘，告别每设备一根线 |
| **Agent（LobeHub 语境）** | 一个"配好人设+模型+规则的 AI 员工"配置。注意：它不是更强的 AI，而是 LLM + 设定 + 记忆的打包 | 不是"更强的专家"，而是"按岗位说明书上岗的那位专家" |
| **上下文（Context）** | 发给 LLM 的"全部已知信息"：人设 + 历史对话 + 你的新消息 + 工具结果；有长度上限（token 预算） | 专家听案前你递过去的"案情材料包"：太厚他看不完，要会精简 |
| **个人记忆（Memory）** | 跨会话长期保存的"关于你的信息"（LobeHub 的特色：白盒、可编辑） | 专家手边的客户档案本，而非每次从零开始 |

## 工程与协作

| 名词 | 人话解释 | 类比 |
|---|---|---|
| **Git** | 代码的版本管理工具：每次改动存一个"存档点"，可回退、可分叉 | 游戏的存档系统：随时读档、开新周目，不会一错全错 |
| **commit（提交）** | 把一次改动存成"存档点"，附带一句话说明 | 存一次档，写一句"这次改了啥" |
| **分支（branch）** | 从主线分出一条平行开发线，互不干扰，完成后再合回 | 另开一条产线试新配方，成功后并入主线 |
| **monorepo** | 一个大仓库装多个子项目（LobeHub：网页+桌面+CLI+80 个内部包全在一个 repo） | 一个大厂区装多个车间，共用围墙、仓库和规章制度 |
| **npm / pnpm** | JS 世界的"应用商店+安装器"：把别人写好的代码包（库）装进你的项目；pnpm 是装得更快更省盘的版本 | 宜家零件仓：别人做好的门把手直接买，不用自己锻造 |
| **node_modules** | npm/pnpm 装的所有第三方库堆在一起的文件夹（很大，**永远不要提交进 Git**，已在 .gitignore 里） | 你从零件仓运来的所有零件堆 |
| **依赖（dependency）** | 你的项目用到的第三方库（写在 package.json 里） | 购物清单：列明"本店用了哪些外购件" |
| **package.json** | 项目的"身份证+购物清单"：项目名、版本、依赖、可运行的命令都在这 | 门店的营业执照 + 进货清单 |
| **Docker** | 把程序+它需要的所有环境打包成"集装箱"，在任何机器上一键运行，"在我电脑上能跑"问题消失 | 集装箱：不管什么码头（服务器），箱子一放就能运转 |
| **Vercel** | 最主流的网页部署平台（LobeHub 官方部署在 Vercel） | 连锁店的"标准门面加盟系统"：代码一推，自动开店 |
| **CI（持续集成）** | 每次提交代码，服务器自动跑检查（测试/lint/类型检查）和构建，不合格就不许合入 | 质检流水线：每批货出厂前自动过检测台 |
| **lint** | 代码风格/低级错误自动检查（分号、命名、未使用变量…） | 编辑部的"校对员"：不改内容，只挑格式和笔误 |
| **单元测试（unit test）** | 针对一小段函数/组件的自动化测试（LobeHub 有 3900+ 个） | 零件级质检：这个螺丝单独测，不装整机 |
| **E2E 测试** | 模拟真人操作整个流程的测试（LobeHub 用 Playwright 驱动真实浏览器） | 验收演练：假想顾客真的走一遍"下单-付款-收货"全流程 |
| **i18n** | 国际化：程序里所有文案外置成"语言文件"，切语言 = 换文件（LobeHub 支持 20+ 语言） | 菜单印多语种，切换语言就是换菜单，不重做厨房 |
| **环境变量（env）** | 不改代码就能调整的配置（从系统读：API key、数据库地址、开关） | 店招后面的"可擦写黑板"：换招牌不用重装门 |
| **AGENTS.md** | 放在项目里、专门给 AI 编码助手看的"开发守则"（LobeHub 有，**你的项目也应该有一份**） | 给施工队的项目说明书：进场规矩、材料规矩、验收标准 |
| **SDK** | 某服务官方提供的"工具包"，把复杂调用封装成几个好用的函数 | 官方配好的"操作手套"：不用徒手拧螺丝 |
| **PWA / Electron** | （见前端部分）把网页变"App"的两种路线：PWA 是"装在手机上的网页"，Electron 是"套壳成独立桌面程序"（VS Code、LobeHub 桌面版都是） | 前者是"手机 App 化"，后者是"把网页搬进独立盒子" |
| **CRA 式脚手架 / CLI** | （LobeHub 有 `apps/cli`）命令行工具：在终端里敲命令完成任务，不用开网页 | 后厨的"快捷按键"：不用走前厅流程，按一下直接出成品 |

## 和"复刻"直接相关的三个判断

1. **LobeHub 的技术栈很新很全**（Next.js 16、React 19、tRPC 11…）。
   你复刻时**不必照抄版本**，用当前主流稳定的组合即可，甚至故意选简单一点的
   （比如后端先不用 tRPC，用普通 API）。
2. **lobe-ui / lobe-icons 是 MIT 的**，直接 `npm install` 就能拥有 LobeHub 的外观——
   这是"复刻"性价比最高的一步（详见 [03](./03-复刻蓝图-核心与可裁剪.md)）。
3. **AGENTS.md 是 vibe coding 的杠杆**：LobeHub 用它约束自家 AI 助手的行为，
   你也应该从第一天就让 AI 给你的项目写一份（见 [04](./04-vibecoding实操路线图.md)）。
