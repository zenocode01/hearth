# 01 · 大白话：LobeHub 是什么

> 目标：不用任何编程背景，也能看懂 LobeHub 是个什么东西、怎么运转的。
> 看不懂的名词，查 [02 词汇表](./02-小白词汇表.md)。

## 1. 一句话版本

**LobeHub 是一个"和 AI 聊天的网页 + 管理一队 AI 员工的工作台"。**

把公司想象成一个办公楼：

- **每个 AI（叫 Agent）= 一名员工**。你有"全能助手"、"翻译"、"写作"等不同岗位。
- **LobeHub = 这家公司**：负责招聘（创建 Agent）、写岗位说明书（设定 AI 的人设和规则）、
  派活（发消息、定时任务）、存档（记住聊过的历史和你的偏好）。
- **AI 本人的"脑子"不在这里**。LobeHub 自己**不做 AI**，它是"包工头"：
  把任务转发给 OpenAI、Anthropic、阿里通义等大模型厂商，把回答转回给你。
  大模型 = 外聘的专家，LobeHub = 对接专家的前台兼行政。

> 这句话是理解一切的钥匙：**LobeHub 不生产 AI，它生产"和 AI 协作的体验"。**
> 所以复刻它，核心不是复刻 AI，而是复刻"管理 AI 的那套系统"。

## 2. 用户视角：一天怎么用

1. 打开网页 → 登录账号
2. 左侧边栏是 **Agent 列表**（你的 AI 员工们），点一个进入对话
3. 在底部输入框打字发送 → AI **一个字一个字地**把回答"打"出来（打字机效果）
4. 右上角可以 **管理这个 Agent**：改名、换头像、改人设（"你是一位资深后端工程师…"）、
   换它用的大模型、调"发挥自由度"（温度）
5. 左侧还能建 **会话/话题**：每个话题独立存档，随时回看、删除
6. 进阶玩法：让多个 Agent 组成小组协作、给 Agent 定时派活（"每天 9 点总结新闻"）、
   接上你的飞书/微信让它住进 IM、给它装"技能"（查网页、算数学、生成图片）

## 3. 一条消息的旅行（内部怎么跑起来的）

```
你打字发送
   │
   ▼
① 前端（网页）：把你的字发出去
   │
   ▼
② 服务端：收到请求，查出这个 Agent 的设定 + 你们的历史消息
   │
   ▼
③ 服务端：把"人设 + 历史 + 你的新消息"打包，调用大模型的 API
   │        （OpenAI / Claude / 通义…… 花钱的是这一步）
   ▼
④ 大模型：一个字一个字地回答（流式传输）
   │
   ▼
⑤ 服务端：边收边转发给前端 → 你看到打字机效果
   │
   ▼
⑥ 服务端：这轮对话存进数据库（下次打开还能看到）
```

**要点**：LobeHub 的"服务端"干的是三件事——
**管账号、管数据（历史/设定）、当转发站（你 ↔ 大模型）**。
它的技术含量主要不在"对话"本身，而在**周围那一圈**：
Agent 管理、记忆、定时任务、技能扩展、多端适配、主题系统……

## 4. 技术栈大白话（每个词是什么角色）

| 名字 | 是什么 | 类比 |
|---|---|---|
| **React** | 前端框架，网页界面的积木 | 餐厅的"装修和桌椅"（用户看到的一切） |
| **Vite** | 前端构建工具，把代码加工成浏览器能跑的东西 | 后厨的"备菜台"（把生料加工成成品端出去） |
| **Next.js** | 全栈框架，网页壳 + 服务端一体 | 店的"大门 + 传菜口"（网页入口和接口都从这进） |
| **TypeScript** | 带"类型检查"的 JavaScript，写错会在运行前报错 | 填表时有"必填项校验"，防止填错 |
| **tRPC** | 前后端通信方式，调用后端像调用本地函数，参数自动校验 | 餐厅内部"对讲机"（前厅后厨直接喊话，不走电话转接） |
| **Zustand** | 前端"状态"管理（界面当前处于什么情况的记录本） | 服务台的"便签墙"（哪桌点过什么、做到哪一步） |
| **SWR** | 数据获取+缓存库（自动帮你取数据、缓存、刷新） | 跑腿小哥（你去厨房取菜，他跑 3 趟还是 1 趟他自己记着） |
| **PostgreSQL** | 数据库（存对话、账号、设定的地方） | 仓库（所有货都有货架编号） |
| **Drizzle** | 操作数据库的工具（ORM），用代码代替手写 SQL | 仓库管理员的"货架规则手册"（不用自己背格子号） |
| **SSE** | 服务器向浏览器持续推送数据的技术（打字机效果的实现方式） | 广播电台（AI 边想边播，你边听边显示） |
| **Electron** | 把网页打包成桌面 App 的技术 | 把"网店"搬进"实体店"（同一套货，换个门脸） |
| **lobe-ui** | LobeHub 自家的 UI 组件库（MIT 协议，你可以直接用） | 一整套"宜家家具"（按钮、弹窗、菜单，现成套件） |
| **lobe-icons** | LobeHub 的 AI 品牌图标库（MIT，可直接用） | 一墙"名牌 LOGO"（OpenAI、Claude 的图标） |
| **i18n** | 国际化（同一套程序支持中/英/日…多语言） | 菜单印多份语言版本，切换语言 = 换菜单 |
| **monorepo** | 一个代码仓库里装多个子项目（LobeHub 是这种结构） | 一个大厂区里分了很多车间，共用围墙和仓库 |

**LobeHub 的完整技术栈一句话版**：
> 前端 = React + Vite 构建的"单页应用"，样式用 lobe-ui/antd；
> 后端 = Next.js + tRPC + PostgreSQL(Drizzle)；
> 桌面版 = Electron 套壳；多个"子应用"和一个"大仓库"组织在一起（monorepo）。

## 5. 代码放在哪（目录地图·人话版）

LobeHub 是 monorepo（一个大仓库装很多项目）。只标你要知道的：

```
lobe-chat/
├── src/                      ★ 网页主体（你看到的那个界面）
│   ├── features/             ★ 164 个"功能块"（Agent 管理、对话、文档…一个功能一个文件夹）
│   ├── store/                ★ 37 个"记录本"（前端状态，比如当前打开哪个会话）
│   ├── routes/               网页的"页面"（都很薄，真正逻辑在 features 里）
│   └── services/             前端怎么调后端接口（统一入口）
├── apps/
│   ├── desktop/              桌面版（Electron）
│   ├── server/               独立后端服务（定时任务、回调等"不能住在网页里"的活）
│   └── cli/                  命令行工具
├── packages/                 ★ 内部零件库（~80 个小包）
│   ├── model-runtime/        各家大模型的"接口适配器"（50+ 家：OpenAI/Anthropic/通义…）
│   ├── agent-runtime/        Agent 运行核心（对话循环、多 Agent 编排）
│   ├── builtin-tool-*/       30+ 个"技能"（一个技能一个包：计算器/查网页/生成图片…）
│   ├── database/             数据库表定义 + 读写代码（71 张表）
│   ├── chat-adapter-*/       飞书/Slack/微信…IM 桥
│   └── locales/              所有语言的翻译文案
├── DESIGN.md                 ★ 设计规范（颜色/字体/间距/文案语气，机器可读的 YAML）
├── AGENTS.md                 ★ 给 AI 编码助手看的"开发守则"（本项目也有！）
└── .agents/skills/           45 份写给 AI 的开发细则（每个主题一份）
```

三个最值得记住的"零件"：

1. **`packages/model-runtime/`** —— 50+ 个大模型的适配器。想让它支持哪家 AI，
   就是在这里加一个适配器。**你复刻时，这一层可以从"只做 1~2 家"开始。**
2. **`src/features/`** —— 功能块仓库。想复刻哪个功能，先来这找它长什么样。
3. **`packages/builtin-tool-*/`** —— 一个"技能"一个包。LobeHub 的设计哲学：
   **每个可扩展的东西都独立成包**，方便单独测试、单独加删。

## 6. 它有多大？为什么这么大？

| 指标 | 数字 |
|---|---|
| 源代码文件（.ts/.tsx） | **15,022 个** |
| 代码行数 | **约 150 万行**（src 约 88 万 + packages 约 53 万 + apps） |
| 测试文件 | 3,900+ 个 |
| 数据库表 | 71 张 |
| 内置"技能" | 30+ 个独立包 |
| 大模型适配器 | 50+ 家 |
| 数据库外的"大仓库" | 还有一个私有的云 SaaS 仓库（开源版里是占位符） |

**为什么这么大**：它是 3 年+ 持续迭代的商业产品，堆满了"高级功能"
（多 Agent 协作、定时任务、评估系统、可观测性、IM 网关、桌面端、CLI……）。
**其中很多功能你用不到，也完全不必复刻** —— 这就是 [03 蓝图](./03-复刻蓝图-核心与可裁剪.md)
要帮你想清楚的事。

## 7. 读完这章，你应该能回答

- LobeHub 自己**不生产 AI**，它是"管理 AI 员工的系统"（Agent 管理 + 记忆 + 转发）
- 一条消息的路径：**你 → 前端 → 服务端 → 大模型 API → 服务端 → 你**，最后存档
- 它的代码 = 网页（src）+ 独立服务（apps）+ 零件库（packages），装在一个大仓库里
- 150 万行里有大量你用不到的功能，**复刻 = 挑功能，不是抄行数**
