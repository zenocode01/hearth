# 03 · 复刻蓝图：核心与可裁剪

> 目标：帮你想清楚"复刻 = 挑功能"，而不是"抄行数"。
> 读完你能：① 知道每个功能属于哪一层；② 对着勾选表圈出自己要的；
> ③ 知道每个功能"简化版怎么做"。

## 1. 先立规矩：什么叫"复刻"

| 复刻方式 | 说明 | 建议 |
|---|---|---|
| ❌ 逐行复刻 150 万行 | 大团队 3 年的产物，包含大量商业/工程设施（评估系统、可观测性、云 SaaS 对接…），个人+AI 复刻不现实，也没必要 | 不做 |
| ✅ **功能复刻（推荐）** | 以"用户能感知到的功能"为单位逐个实现，实现用**简化版**：够用、好懂、好改 | **就按这个走** |
| ⚠️ Fork 后魔改 | 直接拿 LobeHub 源码改。个人学习可行（Apache-2.0 基础部分），但商用发行要买授权（见 [05](./05-许可证与合规.md)）；且 150 万行对小白是灾难现场 | 谨慎 |

**功能复刻的合理预期**：几万行代码（LobeHub 的 3~5%），
覆盖 **80% 的日常使用体验**（聊天、Agent 管理、记忆、主题、文件、基础工具）。
剩下 20% 是高级商业功能，砍掉不影响你自用。

## 2. 功能金字塔（三层）

### L1 · 核心（必须有，没有它就不是"聊天应用"）

| # | 功能 | 用户价值 | LobeHub 在哪实现（参考点） | 你的简化版怎么做 |
|---|---|---|---|---|
| 1 | **聊天界面 + 流式回复** | 能打字、能看到 AI 逐字回答 | `src/features/Chat` + `packages/fetch-sse`（SSE 收流） | 一个页面：输入框 + 消息列表；调大模型 API 的"流式"接口，前端逐字渲染。**第一个就该做的** |
| 2 | **会话/话题管理** | 聊天存档、左栏列表、新建/删除/改名 | `src/store/chat` + `packages/database`（messages/topics 表） | SQLite 建 `topics`、`messages` 两张表；左侧列表 + 选中切换 + 删除 |
| 3 | **Agent 管理** | 创建多个"AI 员工"：名字/头像/人设/模型/温度，各自独立 | `src/features/AgentBuilder` + `agents` 表 | `agents` 表（人设就是一个大文本字段 + 模型选择）；一个编辑页 + 列表页 |
| 4 | **模型与密钥配置** | 填 API key、选模型、测连接 | `packages/model-runtime`（50+ 适配器）+ `model-bank` + 设置页 | 只做 **1~2 家**（如 OpenAI 兼容接口 + 通义）；key 存数据库；"测试连接"按钮 |
| 5 | **Markdown 渲染 + 代码高亮** | AI 的回答排版好看（标题/列表/代码块） | `@lobehub/editor`（MIT 可用）或 react-markdown + shiki | `react-markdown` + `shiki` 代码高亮，**半天工作量** |
| 6 | **账号/单用户** | 知道"这是你的数据" | better-auth（邮箱登录/passkey/OAuth） | 起步可以**先不做登录**（本地自用）；要的话一个"邮箱+密码"页 + 会话凭证即可，别一上来做 OAuth |

### L2 · 进阶（多数人的"需要"，按你口味选）

| #   | 功能                         | 用户价值               | LobeHub 在哪实现                                         | 你的简化版怎么做                                                           | 砍？  |
| --- | -------------------------- | ------------------ | ---------------------------------------------------- | ------------------------------------------------------------------ | --- |
| 7   | **主题系统**（深浅色 + 主色）         | 外观跟 LobeHub 一样     | lobe-ui 的 token 体系（DESIGN.md 有完整定义）                  | **直接用 lobe-ui（MIT）**，主题切换是现成的                                      | ☐   |
| 8   | **中/英文切换（i18n）**           | 多语言                | `packages/locales` + react-i18next                   | i18next 两语言文件；或先用单语言，后补                                            | √   |
| 9   | **文件上传**（图片/文档给 AI 看）      | 发图给 AI 分析、传文档总结    | `packages/file-loaders` + S3 存储                      | 图片：存本地/云盘，按模型能力转 base64/URL 发给 API；文档：先只做图片                        | ☐   |
| 10  | **图片生成**                   | 对话中出图              | `builtin-tool-image-generation`（调 fal/OpenAI images） | 加一个"生成图片"按钮 → 调 API → 图片进对话                                        | √   |
| 11  | **工具调用（Function Calling）** | AI 能算数、查网页         | `packages/tool-runtime` + 30+ `builtin-tool-*`       | **从 1~2 个工具开始**：计算器 + 网页搜索（各 ~200 行）；机制学 `builtin-tool-calculator` | ☐   |
| 12  | **MCP 接入**                 | 一个协议接一堆第三方工具       | `@modelcontextprotocol/sdk`                          | 看懂 11 再做；本质是"把 MCP 服务器的工具列表并进 11 的工具列表"                            | ☐   |
| 13  | **个人记忆**                   | Agent 记住你的偏好，跨会话生效 | `packages/memory-user-memory`（结构化、可编辑、白盒）            | `user_memory` 表 + "我的记忆"编辑页；对话前把相关记忆拼进上下文                          | ☐   |
| 14  | **移动端适配**                  | 手机也能用              | `(mobile)` 路由组 + 移动端组件变体                             | CSS 响应式（同一套页面自适应）；LobeHub 的"移动端独立 SPA"是过度设计，**不要学**                | ☐   |
| 15  | **导出/备份**                  | 聊天记录能带走            | 分享页 + JSON 导出                                        | 一键导出 .json / .md（~100 行）                                           | ☐   |

### L3 · 高级（LobeHub 的"哇"功能，**建议全部先砍**）

| 功能 | 它是干嘛的 | 为什么砍 |
|---|---|---|
| 多 Agent 小组协作（Agent Groups） | 多个 AI 组队并行干活、互相迭代 | 需要 `groupOrchestration` 整套编排引擎，复杂度指数级上升；等 L1/L2 稳了再说 |
| 定时任务（Schedule） | "每天 9 点自动跑"无人值守 | 需要可靠的后台任务系统（LobeHub 用 Upstash Workflow）；先用系统 crontab/计划任务顶替 |
| IM 网关（飞书/Slack/微信…） | Agent 住进你的 IM | 每家 IM 一个 `chat-adapter-*`；先把核心做好，IM 是"锦上添花" |
| 桌面端（Electron） | 装到电脑上的 App | 套壳工程量大（签名/自动更新/沙箱）；Web 版能用前不碰 |
| Agent 市场/分享（Agent Market） | 别人做好的 Agent 一键安装 | 需要开放 API + 审核 + 安全沙箱，商业级工程 |
| 评估/基准测试（Eval） | 给 Agent 打分、回归测试质量 | 研究/商业设施，自用最不到 |
| 可观测性（Langfuse/OTel 追踪） | 全链路日志、token 成本监控 | 出问题后再加不迟；先靠 console + 日志文件 |
| CLI / 插件系统 / 知识库 / 文档协作 | 命令行工具 / 第三方插件 / RAG 知识库 / 多人文档 | 全是独立的大工程，属于"第二个产品" |

## 4. 给小白的技术选型建议（比 LobeHub 简单一档，故意）

LobeHub 是"大厂配方"，你复刻是"家用配方"。同样的功能，选更简单、
资料更多、AI 更熟的技术：

| 层 | LobeHub（大厂配方） | 你的简化版（家用配方） |
|---|---|---|
| 框架 | Next.js 16 壳 + Vite 多 SPA | **Next.js 单项目**（App Router，前后端一体，一个仓库） |
| 前后端通信 | tRPC（复杂但类型安全） | **普通 API 路由**（`/api/chat` 这种 REST）；熟练后再升级 tRPC |
| 数据库 | PostgreSQL + Drizzle（71 张表） | **SQLite + Drizzle**（一个文件，零运维；Drizzle 对 SQLite 支持极好，以后可平滑换 PostgreSQL） |
| 前端状态 | 37 个 zustand store + SWR | 起步：**组件内状态 + React Query/SWR 一个**；需要时再拆 store |
| 样式/组件 | antd + antd-style + lobe-ui token | **直接装 `@lobehub/ui`（MIT）**：它的组件本身就基于 antd，装完就有 LobeHub 的观感 |
| 图标 | `@lobehub/icons`（MIT） | 同左，直接用 |
| 鉴权 | better-auth（邮箱/passkey/OAuth 全家桶） | 起步零登录（本地）；需要时 `better-auth` 或 next-auth 单模式 |
| 流式 | 自研 `fetch-sse` | **`ai` 包（Vercel AI SDK）的 streamText**：一行代码搞定流式，文档极多，AI 助手很熟 |
| 部署 | Vercel / Docker（多服务 compose） | 先 `npx vercel` 一键部署或本地 `npm run dev`；Docker 最后再说 |

> 为什么故意降级：vibe coding 的失败率主要来自"技术太新太偏，AI 生成的代码
> 你自己读不懂、改不动"。选 AI 语料库里的"大路货"，出错率低、你自己
> 将来接手也容易。**LobeHub 的架构思想学，具体实现抄它的"简单等价物"。**

## 5. 你的仓库长什么样（对照 LobeHub）

LobeHub 是 monorepo（大厂区多车间）。**你初期不是**，就是一个项目：

```
Hearth/
├── app/                    # Next.js：页面 + API 路由
│   ├── (chat)/             #   聊天主界面（= LobeHub 的 src/routes + features/Chat 的简化）
│   ├── agents/             #   Agent 管理（= AgentBuilder 的简化）
│   ├── settings/           #   模型/密钥/主题（= settings 的简化）
│   └── api/                #   接口：/api/chat /api/agents /api/models…（= tRPC 的简化）
├── lib/
│   ├── db/                 #   SQLite + Drizzle：schema + 连接（= packages/database 的 1/10）
│   └── llm/                #   模型适配：1~2 家 provider（= packages/model-runtime 的 1/20）
├── components/             #   自拼的小组件（优先用 @lobehub/ui 现成的）
├── AGENTS.md               # ★ 给 AI 助手的项目守则（从第一天就建，见 04）
└── refs/lobe-chat/         # 参考书（已就位，只读，不参与构建）
```

**对照关系**：你的每个目录 ≈ LobeHub 某个"车间"的 1/10 规模。
以后某块长大了（比如工具越来越多），再像 LobeHub 那样拆成独立包/子项目
——**从单体长到 monorepo，而不是从 monorepo 学起。**
