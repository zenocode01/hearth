# 04 · vibe coding 实操路线图

> 目标：照着做就能开始。每阶段 = 一个"用户能验收"的小目标。
> 前提：你已按 [03](./03-复刻蓝图-核心与可裁剪.md) §3 圈好了功能清单。
> 技术组合（家用配方）：**Next.js + SQLite + Drizzle + Vercel AI SDK + @lobehub/ui**。

## 1. 一次性环境准备（约 30 分钟）

| 装什么 | 干嘛的 | 怎么装 |
|---|---|---|
| **Node.js**（LTS 版） | 运行 JS/TS 的引擎，一切的底座 | 去 nodejs.org 下 LTS 安装包，装完终端敲 `node -v` 看到版本号即成功 |
| **Git** | 版本管理（每次改动存"存档点"） | 一般随编辑器一起有；`git --version` 验证 |
| **VS Code**（或你顺手的编辑器 + 你用的 AI 助手客户端） | 写代码的地方 | 装好即可 |
| 大模型 API key | 你的应用要调 AI 的"会员卡" | 在你选的模型厂商后台申请（见 [02 词汇表](./02-小白词汇表.md)：API key） |

> 提示：如果你用 AI 编码助手（Cursor / Claude Code / pi 等），**把这篇文档和
> 03 蓝图的路径直接丢给它**，让它"先读这两份文档再开始"——这就是喂参考。

## 2. vibe coding 的 5 条纪律（小白最容易死在这里）

1. **小步**：一次只让 AI 做一个小功能（一个按钮、一个接口、一张表）。
   一次说"把整个 App 做了" = 得到一堆读不懂的烂代码。
2. **随时能跑**：每个小步结束，**亲自打开页面点一遍**。项目任何时刻都应该是能跑的。
3. **勤存档**：一个功能跑通了 → `git commit`（让 AI 提交并写清楚改了什么）。
   跑挂了随时回退。**没有 commit 的 vibe coding = 没有存档的游戏。**
4. **喂参考**：卡住或要新风格时，让 AI 去读 `refs/lobe-chat` 对应部分：
   "参考 refs/lobe-chat/src/features/Agent Builder 的做法，给咱们写一个简化版"
   ——学它的**思路和结构**，让它写**自己的代码**（别让它复制粘贴，见 [05](./05-许可证与合规.md)）。
5. **第一天就建 AGENTS.md**：让 AI 在你的项目根目录写一份给 AI 助手看的守则
   （项目结构、技术选型、编码约定、"永远保持项目可运行、小步提交"）。
   LobeHub 自己就靠这东西 + 45 份 skills 约束 AI 行为（它的 AGENTS.md 可以直接当模板抄）。

## 3. 五阶段计划

> 每个阶段：**目标**（用户视角）→ **怎么对 AI 说**（提示词模板，按你的清单改）
> → **验收**（你自己点什么算通过）。阶段间无依赖可并行的，先按顺序走，熟了再合并。

### 阶段 0 · 项目骨架（半天）

**目标**：打开 `http://localhost:3000` 能看到一个 LobeHub 风格的空页面。

**对 AI 说**：
> "我们要开始复刻 LobeHub 的简化版（参考 docs/replica/03）。请初始化 Next.js 项目：
> Typescript + App Router；安装 @lobehub/ui、@lobehub/icons、@lobehub/editor、
> Vercel AI SDK、drizzle + better-sqlite3；建好 AGENTS.md（参考 refs/lobe-chat/AGENTS.md
> 的结构写我们的版本）；做一个 / 路由展示 lobe-ui 的按钮和输入框，支持深浅色切换。"

**验收**：✅ 页面能打开；✅ 深浅色切换正常；✅ AGENTS.md 存在且内容合理。

### 阶段 1 · 能聊天的页面（1~2 天）★ 最重要

**目标**：输入一句话，看到 AI **逐字**回答。

**对 AI 说**：
> "做一个 /chat 页面：顶部 Agent 名称，中间消息列表（用户/AI 气泡区分），
> 底部输入框。用 Vercel AI SDK 的 streamText 调【你选的模型，如 OpenAI 兼容接口/通义】，
> API key 从环境变量读。要求：流式逐字渲染；AI 回答支持 Markdown（用 @lobehub/editor
> 或 react-markdown）；代码块要有高亮和复制按钮；请求失败要有友好错误提示。
> 参考 refs/lobe-chat 里 src/features/Chat 的消息结构和 src/libs 的 SSE 处理方式，
> 但用我们自己的简化实现。"

**验收**：✅ 问"1+1等于几"能看到逐字打字效果；✅ 断网/写错 key 时有可读的错误提示；
✅ 刷新页面后……（还没有持久化，这正是下一阶段的活儿）。

### 阶段 2 · 记忆住：会话与持久化（1~2 天）

**目标**：聊天刷新不丢；左侧有会话列表，可新建/改名/删除。

**对 AI 说**：
> "加 SQLite + Drizzle：topics（id/标题/创建时间）和 messages（id/会话id/角色/内容/时间）
> 两张表，写迁移。/api/topics 增删改查；/api/chat 把每轮对话写入数据库；
> 左侧边栏渲染会话列表（点击切换、新建、删除、自动用首条消息做标题）。
> 表结构设计可参考 refs/lobe-chat/packages/database/src/schemas 里 messages/topics 的字段，
> 只保留我们需要的列。"

**验收**：✅ 刷新不丢；✅ 重启服务不丢（数据在 .db 文件里）；✅ 删掉的会话查不到。

### 阶段 3 · Agent 管理（1~2 天）

**目标**：创建多个"AI 员工"，各有名字/头像/人设/模型；对话时按所选 Agent 的行为说话。

**对 AI 说**：
> "加 agents 表（名称/头像/系统提示词/模型名/温度/创建时间）；/agents 列表页 +
> 新建/编辑页（表单：名称、头像上传、系统提示词多行文本、模型下拉、温度滑杆、'测试'按钮
> 发一句固定问题验证人设生效）。聊天页顶部加 Agent 选择器；发送时把该 Agent 的系统提示词
> 拼进请求。参考 refs/lobe-chat/src/features/AgentBuilder 的字段和交互，做我们的简化版。"

**验收**：✅ 建一个"资深后端"和一个"段子手"，各问同一个问题，回答风格明显不同；
✅ 改完人设立刻生效；✅ 头像能换。

### 阶段 4 · 打磨（1~2 天）

**目标**：用起来舒服、不丑、不出低级错。

**对 AI 说**（挑你要的）：
> "① 主题：接入 lobe-ui 的主题 token（主色可选、深/浅色，参考 refs/lobe-chat/DESIGN.md）；
> ② 中/英切换（i18next，先做这两个语言）；
> ③ 所有界面补上 空/加载/错误 三态（列表空、请求转圈、失败有重试）；
> ④ 移动端响应式（手机竖屏可用）；
> ⑤ 导出：会话一键导出 .md / .json。"

**验收**：✅ 手机浏览器打开能正常聊；✅ 断网/错误 key 时每个页面都有可读状态；
✅ 切换语言所有文案跟着变；✅ 导出的 .md 能在别的软件里正常打开。

### 阶段 5 · 扩展（按你圈的清单，每项 1 天上下）

按 [03](./03-复刻蓝图-核心与可裁剪.md) §3 勾选表逐项做，每项都是独立小工程：

- **图片发给 AI**：输入框加附件；图片存本地/uploads；按所选模型的多模态接口发送
  （参考 `refs/lobe-chat/packages/file-loaders` 的读文件方式，简化版）
- **AI 生成图片**：对话里"生成图片"按钮 → 调图像生成 API → 图片气泡入会话
- **工具（计算器/搜索）**：学 `refs/lobe-chat/packages/builtin-tool-calculator`
  的"一个工具 = 一个目录（元数据 + 执行函数 + 测试）"模式；先做 1 个，跑通"AI 决定调用 →
  执行 → 结果回灌 → 继续回答"的完整循环（这个循环就是 Function Calling 的全部）
- **MCP**：上一步稳了之后，用 `@modelcontextprotocol/sdk` 把 MCP 服务器的工具列表
  并进我们的工具列表
- **个人记忆**：`user_memory` 表 + "我的记忆"编辑页 + 对话前把相关条目拼进系统提示词
  （参考 `refs/lobe-chat/packages/memory-user-memory` 的数据结构）

**验收**：每项单独验收（做完一项 commit 一项）。

## 4. 常见翻车 & 自救（先存好，出事翻这里）

| 症状 | 大概率原因 | 自救 |
|---|---|---|
| 前端"调不到后端"，控制台一堆 CORS 红字 | 前后端跨域（浏览器安全规则） | 让 AI："把接口改成本站 API 路由"或"加 CORS 白名单"——家用配方里全用 Next 的 API 路由，**天然没有这个问题**，出现即说明架构歪了，让它重构 |
| AI 回答是"一坨"一次性出现，没有打字机效果 | 没用流式接口（用了普通请求） | 让 AI："改用 streamText / SSE，参考 refs/lobe-chat 的 fetch-sse" |
| 数据重启就没了 | 没写库（只在内存/组件状态里） | 让 AI："把数据落 SQLite，检查写入代码" |
| 页面白屏、控制台一长串红 | 依赖版本打架 / 构建失败 | 把**完整的报错原文**复制给 AI；还不行就 `git reset` 回到上一个 commit 再来 |
| 同一个功能 AI 反复修不好（3 次以上） | 需求描述模糊，或方案太复杂 | **停下来自己说人话**：把"我期望看到什么"一步步写给它（"我点 X，应该看到 Y"）；
  或让 AI 读 refs 里对应的 LobeHub 实现重新对齐思路 |
| 越做越乱，自己看不懂了 | 步子太大 / 没建 AGENTS.md | 暂停新功能，让 AI："写一份当前项目的 ARCHITECTURE 说明，并把约定写进 AGENTS.md"，然后按它重构 |
| 想抄 LobeHub 一段代码 | **停**：主仓库是 LobeHub Community License（改后商用要授权） | 改成"参考它的实现思路"；要现成组件请用 MIT 的 @lobehub/ui / @lobehub/icons（见 [05](./05-许可证与合规.md)） |

## 5. 里程碑自检（全部 ✅ 才算"复刻完成"）

- [ ] 聊天可用：流式、Markdown、代码高亮、错误提示
- [ ] 会话持久化：刷新/重启不丢；列表/新建/删除/改名
- [ ] 多 Agent：人设/模型/温度独立配置，行为可感知差异
- [ ] 模型配置：至少 1 家可配 key + 测试连接
- [ ] 主题：深浅色（+ 主色）
- [ ] 你圈进清单的 L2 功能，逐项完成
- [ ] 每个阶段都有 commit；README 写清"这是什么、怎么跑、用了什么"
- [ ] （可选）部署到 Vercel/一台服务器，手机能访问

> 做完这列，你就拥有了一个"**LobeHub 体验的 80%、代码量的 5%**"的个人版。
> 之后想加什么（IM 网关、小组协作、桌面端），都是在这个稳定底座上"长"出来的，
> 而不是推倒重来。
